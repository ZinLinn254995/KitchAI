# Prompt AI Intake Checklist

Use this checklist when receiving KitchAI files or a repository ZIP. A ZIP is
not required when existing context and available repository state are
sufficient.

## Checklist

- [ ] Read `README.md`, `PROJECT_STATUS.md`, and `docs/TASK_REGISTRY.md` first.
- [ ] Read `AGENTS.md` and only relevant project documents, including the
      [overview](PROJECT_OVERVIEW.md), [product foundation](PRODUCT_FOUNDATION.md),
      [decisions](DECISIONS.md), [roadmap](ROADMAP.md), and
      [Prompt AI workflow](PROMPT_AI_WORKFLOW.md).
- [ ] Understand KitchAI's purpose and distinguish confirmed decisions from
      provisional plans and unresolved questions.
- [ ] Identify current status and active task; separate verified implementation
      from documentation claims and future plans.
- [ ] Identify unresolved decisions material to the next task.
- [ ] Recommend the next useful action without repeating completed work.
- [ ] Consult the owner before expanding scope or treating a proposal as
      approved.
- [ ] Create small coding tasks and self-contained prompts only after owner
      approval of scope.

Do not request another ZIP merely because a new task or chat has started. Follow
the [operating workflow](PROMPT_AI_WORKFLOW.md) for the limited cases where more
files or project access are actually needed.

## Expected First Response

Summarize the available project context before proposing work:

> **Project:** [What KitchAI is.]
>
> **Completed and verified:** [Documented work and evidence; distinguish
> application behavior from documentation checks.]
>
> **In progress or incomplete:** [Current task, unfinished work, or blockers.]
>
> **Next recommended action:** [Smallest useful next step and why.]
>
> **Owner input needed:** [Only material unresolved decision(s), or “None for
> this step.”]

Continue from the recorded state; do not restart discovery without a concrete
gap or conflict.
